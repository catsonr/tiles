## the two authorized departures from the contract

carson asked for both after seeing what the contract's version sounded like. they
are recorded here rather than argued with.

### rotate is directional, so the signal payload changed

the contract forbids choosing a variant from a payload field, and
`orientation_changed(entry, orientation)` had no direction in it to choose from.
carson wants cw on cw and ccw on ccw, so the producer changed:

```text
LevelPlayer  orientation_changed(entry, orientation)
                → orientation_changed(entry, orientation, forward)
Exam         forwards the third argument unchanged
```

`forward` is the direction the player *asked for*, not a property of the
orientation they landed on — cycling backward to the same index is still a
backward turn. it is the only payload field any cue reads; entry, orientation,
proposal, index, and number are all still ignored.

the two directions are two cues with two one-variant randomizers, rather than one
cue with a manually chosen stream. so the structure is unchanged — every bucket
is still "one randomizer, picked at random inside it" — and either direction can
grow more variants later without any code change.

**`forward` is mapped to `rotate_cw`.** `R` is forward, `shift-R` is backward. i
have not seen which way a tile visually turns on `R`, so if it is backwards it is
one ternary in `on_orientation_changed`.

## the dependency direction

the director reaches up; the exam never reaches down.

```text
AudioDirector::_ready
    → cast_to<Exam>(get_parent())
    → connect(all eight semantic signals, ...)
```

`Exam.cpp` still names nothing about audio. the rotation-direction argument is a
gameplay fact — which way the player asked to turn — that the exam forwards
without knowing anyone listens, so the exam remains unaware of cues, gain,
players, and playback exactly as before. a director whose parent is not an `Exam`
reports that once and stays inert; the exam plays identically either
way, which the runner proves against a control exam built from the same scene
with its director removed before it ever entered the tree.

the director is a plain `Node` child of the exam scene root, named `Audio`. it
creates its own `AudioStreamPlayer` child in C++ rather than having one authored
in the scene, so the whole voice — stream, loop, gain, lifetime — is owned in one
place. ordinary Godot node ownership frees it.

## the effect buckets

```text
Exam signal                             →  bucket        →  one play()
palette_selected                           palette_select
orientation_changed(…, forward = true)     rotate_cw
orientation_changed(…, forward = false)    rotate_ccw
placement_succeeded                        place
removal_succeeded                          remove_undo

active_proposal_changed(true, …)           hover
active_proposal_changed(false, …)          —              (silent)
victory_reached                            victory        + the duck
problem_changed                            navigate
```

`forward` is the one payload field any cue reads. which entry, which orientation,
which proposal, which index — none of that reaches playback, because within a
bucket the variant is the randomizer's choice and never the game's.

there is no throttle, debounce, cooldown, queue, or same-frame suppression
anywhere in the director. the producer already rejects unsuccessful and unchanged
operations, so anything that arrives here is a real result and gets exactly one
`play()`, whether or not that bucket already has voices running.

### where the variant list lives

one `AudioStreamRandomizer` `.tres` per cue, inside its own cue directory. C++
holds six fixed resource paths and nothing else — no directory scan, no filename
construction, no variant list in code. the resource is *only* the list of
streams; the playback policy is applied in `load_effects()` every time:

```text
playback mode              PLAYBACK_RANDOM   (immediate repeats allowed)
weights                    1.0 on every stream, however many there are
random_pitch_semitones     2.0
random_volume_offset_db    1.0

player max polyphony       8
player pitch / volume      1.0 / 0 db
```

so a `.tres` hand-edited in the Godot editor can gain or lose a variant, and it
still cannot change how the cue is played or make one variant more likely than
another.

## the background voice

`res://audio/bgm.mp3` is loaded through `ResourceLoader`, `set_loop(true)` and
`set_loop_offset(0.0)` are applied **in C++**, and `play(0.0)` is called once.

looping is set in code rather than in `bgm.mp3.import` on purpose: the contract's
requirement then lives in one visible place, it is directly readable back by the
runner, and a re-import cannot silently un-loop the track. `bgm.mp3.import` is
whatever `godot --headless --import` generated (`loop=false`) and was not hand
edited.

the source bytes are untouched:

```text
sha-256  cbdd1b838baf43cf9917975b8fc1b30c11bd3681f31a977290ca19353c1ee891
```

that is the hash the contract names, it is the hash in `HEAD`, and it is the hash
in the worktree.

### the two gain components

```text
background volume db = ambient envelope db + victory duck db
```

both are advanced by the same delta in `AudioDirector::advance(delta)`, which is
what `_process` calls and what every test calls. neither component reads the
other. that is the whole reason a victory during an absent hold is inaudible and
a victory during a fade does not bend that fade: there is no code path where one
could.

fades and duck ramps use `smoothstep`, `t²(3 − 2t)`. it is monotonic on `[0, 1]`,
exact at both ends, and cannot overshoot. the contract left the polynomial open,
so the runner tests the properties — monotone, bounded, exact endpoints — rather
than the curve.

### phase accounting

both state machines consume a delta in a loop:

```text
while remaining > 0:
    left = duration − elapsed
    if remaining < left: elapsed += remaining; stop
    remaining −= left
    begin the next phase
```

a delta larger than the current phase spends the phase exactly, then carries the
remainder forward. a 10 000-second delta lands in a well-formed phase, not past
one. holds sit exactly on their endpoint because the next phase begins at the
value the previous one reached, so the audible gain is continuous across every
boundary by construction rather than by clamping.

durations come from `UtilityFunctions::randf_range` — Godot's global RNG, which
Godot 4 seeds itself. no seed, no saved sequence, no gameplay contact.

### the duck restart

`on_victory_reached` captures `duck_from_db_ = duck_db()` and restarts the attack
from there. so a second victory during a hold attacks from `-12` to `-12` (a flat
0.15 s), and during a release at `-6` attacks from `-6` to `-12`. it can never
sum past `-12`, which the runner checks by sampling the whole restarted attack.

## three things worth knowing

**1. the "2 ObjectDB instances were leaked" line at exit is Godot's, not ours.**
a bare scene containing nothing but an `AudioStreamPlayer` autoplaying
`bgm.mp3` leaks exactly the same `AudioStreamMP3` and `AudioStreamPlaybackMP3` at
headless exit. adding `stop()` and `stream = null` on `NOTIFICATION_EXIT_TREE`
and `NOTIFICATION_PREDELETE` changes nothing. i verified both directly with
throwaway scenes under `res://.godot/` and deleted them. the count scales with
how many exams a runner built, which is why the audio runner reports 7. i did not
add a shutdown workaround: a plain Godot scene does exactly what we do, and a
workaround would only hide a future real leak.

**2. `Invalid polygon data, triangulation failed` is pre-existing and unrelated
to audio.** it appears whenever the authored exam is navigated off problem 24 and
the result gets drawn headlessly. i confirmed it with audio entirely absent — a
control exam built from the same scene with its director removed first raises it
too, once per exam. it is a renderer complaint about a footprint polygon in one
of the early authored problems, it does not fail any exact check, and act 3 is
forbidden from touching level content or unrelated presentation, so i left it.
**worth a look before release.**

**3. test scenes ship in the pack.** `export_filter="all_resources"` packages
`res://tests/*.tscn`, so `audio_integration.tscn` joined the four which were
already going out. pre-existing, out of scope here, one `exclude_filter` away.

## left to carson

everything only ears can settle. carson is the test case for all of it, and
specifically:

- **is `-6 db` actually half?** the plateau moved from `0 db` to `-6 db` on the
  reading that "half volume" means half amplitude. `-10 db` is the other reading.
  one constant.
- **victory against the duck.** `-12 db` under five variants of a victory sound
  i have never heard, with a 0.15 s attack. if the duck swallows the cue, or if
  the cue doesn't need that much room, this is the pair to tune together.
- **undo at ±2 semitones and ±1 db.** two variants means you hear the same two
  sounds a lot. the pitch spread is what keeps that from turning into a tic;
  whether 2 semitones is enough spread for *these* two files is a listening call.
- **hover is the one to break first.** every accepted ghost change plays a cue,
  with no throttle by contract, from a single source file. sweeping the pointer
  fast across a dense board is *the* test. if it's too much, the fix is a quieter
  or shorter source file — or more variants — not a debounce.
- **which way is `R`?** forward is mapped to `rotate_cw`. if a tile visibly turns
  the other way on `R`, one ternary swaps it.
- **the new envelope ratio.** the holds were inverted so music dominates:

  ```text
                    was            now
  audible hold      35–100 s       60–180 s
  absent hold       25–120 s       15–45 s
  ```

  a literal swap of the two windows would have been almost a no-op — they
  overlapped, and it would have *raised* the minimum silence from 25 s to 35 s —
  so the inversion is of which phase dominates: roughly four seconds of music per
  second of silence, where it used to be about even. if that overshoots, the four
  constants are adjacent in `AudioDirector.cpp`.
- **the fade shape.** smoothstep over 6–12 s in, 8–16 s out. untouched by the
  inversion, so a cycle is now a long stretch of music with a brief dip rather
  than a pulse. if the fades feel like they arrive late and then rush, the curve
  is one function, `smooth`.
- **the seamless loop.** ~207 s, and the audible hold alone can now run 180 s, so
  you will cross the loop boundary while listening far more often than before.
  that is the seam to judge. nothing automated can hear it.
